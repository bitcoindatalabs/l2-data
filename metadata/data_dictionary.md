# Data dictionary (schema 1.0)

Generated by `shared.l2.common.schema.describe_markdown()`; do not edit by hand.

## Conventions

- **amounts:** integer satoshis
- **times:** UTC Unix seconds (chain header times)
- **txids:** lowercase hex, display order
- **heights:** integers; btc_* = Bitcoin, l2_* = the L2
- **row identity:** l2 + instance

## Verification classes

- `bitcoin_verified`: Read from Bitcoin blocks alone. Anyone with a Bitcoin node can recompute it.
- `l2_chain_verified`: Read from the L2's own chain alone (Liquid blocks). Anyone with an L2 node can recompute it.
- `cross_chain_verified`: Computed from a bitcoin_verified value and an l2_chain_verified value, joined by a stated rule (for example the L2 block mapped to a Bitcoin block by header time). Both inputs are public chain data; the join rule is in `method`.
- `inferred`: Depends on a modelling choice or heuristic named in `method` (for example a classification rule). Not a direct read of either chain.
- `operator_reported`: Taken from the operator's own statements or API. Not checked against a chain.

## Common tables (`common/`)

### `custody`

Bitcoin held on behalf of the L2's users: every Bitcoin output the custodian(s) control, at the end of each UTC day (the day's last Bitcoin block). Grain: one row per L2 instance per UTC day.

| Column | Type | Meaning |
|---|---|---|
| `l2` | string | L2 network: liquid (later ark, spark) |
| `instance` | string | deployment of that L2: liquidv1 (later arkade, second, mainnet) |
| `utc_day` | date32[day] | UTC day of the Bitcoin block's header time |
| `btc_height` | int64 | last Bitcoin block of the day |
| `btc_time` | int64 | its header time |
| `reserve_sats` | int64 | BTC in custody after that block |
| `custody_utxos` | int64 | number of custody outputs after that block |
| `reserve_min_sats` | int64 | lowest reserve after any block of the day |
| `verification_class` | string | how the row's numbers are established (metadata/verification_classes.json) |
| `method` | string | the rule or source behind the row, in words; names the source table(s) |

### `liabilities`

Claims outstanding on the L2 that the custody is meant to back (Liquid: L-BTC supply = peg-ins claimed - peg-outs - explicit burns), at the L2 block mapped to the day's last Bitcoin block. Grain: one row per L2 instance per UTC day.

| Column | Type | Meaning |
|---|---|---|
| `l2` | string | L2 network: liquid (later ark, spark) |
| `instance` | string | deployment of that L2: liquidv1 (later arkade, second, mainnet) |
| `utc_day` | date32[day] | same day as custody.utc_day |
| `btc_height` | int64 | the Bitcoin block it is measured against (custody.btc_height) |
| `l2_height` | int64 | L2 block mapped to that Bitcoin block |
| `l2_time` | int64 | its header time |
| `supply_sats` | int64 | claims outstanding at l2_height |
